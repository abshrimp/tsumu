### 信頼境界の確認表（J-1）

| 経路 | 今回の独立チェック | 現時点の残り |
| --- | --- | --- |
| ZIP → インポート → Canvas → HTML | ZIP構造・パスの検査とCSS終了タグの検査 | 実ブラウザでの全経路再走査 |
| SiteDoc → スクリプト → 外部通信 | 不正SiteDoc拒否と値・参照の検査 | 非同期通信ブロックとの連鎖 |
| 外部API → データ表示 → HTML生成 | コードリテラルと値比較の注入試験 | 外部APIを模したブラウザ動的試験 |
| CSS → プレビュー → 公開 | CSS終了タグの文字列試験 | 完全なブラウザ描画の差分試験 |
| GitHub復元データ → エディタ | SiteDocバリデーターの境界確認 | GitHubモックからの復元全体 |
| AI応答 → SiteDoc変更 → 公開 | SiteDocの不変条件確認 | AI応答からの操作適用・公開 |
| 署名付きアセットURL → データ取得 | URLスキームの比較 | 署名検証・権限境界を跨ぐ試験 |

「残り」にあるものは検証済みとみなさない。個別領域の既存テストがあっても、Jの独立試験が行われたことにはならない。

## 新しい横断発見事項と引き継ぎ

### AUD-J-014: 欠落アセットID参照の検証不一致（Medium候補）

再現条件（統合後想定）：`makeImage()` 相当のノードに `image.assetId = "missing-asset"` を設定し、`doc.assets = {}` の編集データをインポートする。
- PR #26 の `validateImportedDoc` は `image.assetId` が `assets` に存在することを確認しない。
- PR #31 の `validSiteDoc` は `assetRefValid` で欠落を拒否する。
- そのため、ブラウザ保存でインポート直後に保存可能な文書が、再読込時に破損文書として扱われるおそれがある。

静的なコードの比較で確認。統合後のブラウザ再現・修正後の回帰試験は未実施。
参照: PR #26・#32 のJコメント。担当Eに修正を依頼済み。共有ファイルをJで重複変更しない。

### AUD-J-015: 不正ノード設定の検証不一致（Medium候補）

再現条件（統合後想定）：`nodes[id].styles = null` または `nodes[id].type = "unknown-element"` を保存APIへ送る。
- PR #26 は `validImportedNode` / `validStyles` で拒否する。
- PR #31 の `validSiteDoc` はID/children等の不変条件を検査する一方、これらのノード型・設定の検査を欠いている。
- 検証に不一致があるため、不正なデータが保存後のエディタや生成コードを停止させるおそれがある。

静的なコードの比較で確認。実際の保存API経由の再現・修正後の回帰試験は未実施。
参照: PR #31・#32 のJコメント。担当Bに修正を依頼済み。

## 監査中に確認するべきリスク

1. 変異テストは有限個の入力しか調べないため、未知の攻撃経路を否定するものではない。
2. 文字列レベルの安全性は、ブラウザでの実際の実行・SSR・埋め込み先の文脈が安全であることを証明しない。
3. 同時編集の試験は決定的な操作組み合わせであり、ネットワーク断や長時間の多端末競合を完全に模擬していない。
4. 監査A〜Iの未マージの修正、統合HEAD、CodeQLの警告、デプロイ構成は別途確認が必要である。
5. 独立レビューは修正担当のセルフチェックでは代替できない。A〜Iの最終差分と統合環境の確認を残す。

本書は監査証跡であり、全バグ・脆弱性の不存在や総合監査完了を宣言するものではない。
