# 値の作り方（UI試作）

スクリプトの「値を変数とする」を中心に、既存の7種類の処理をブロック内で切り替えられるようにします。

| 画面の選択肢 | 既存の保存形式（kind） |
| --- | --- |
| 値をそのまま入れる | `set-var` |
| リストの件数を数える | `count` |
| リストを文字列につなぐ | `join` |
| 文字列をリストに分ける | `split` |
| リストから1件探す | `array-find` |
| 式を計算する | `calc` |
| 文字列を置き換える | `replace` |

切り替えは既存ブロックの `kind` を明示的に変更するだけです。変数名 `into` とブロック `id` は維持し、操作間で意味が対応する入力欄のみ引き継ぎます。入力条件が変わる場合は空欄に戻し、Undoできるようにします。

**値を作る操作と、副作用のある操作は別です。**

- `array-field` は各項目に値を格納します。単なる「新しい値を作る」処理には含めません。
- `list-edit` は区切り文字つきの**文字列**を変更するもので、JSONのリスト操作ではありません。
- `filter-array` / `unfilter-array` / `sort-array` はリスト**表示**に効くため、純粋なリスト値の加工とは統合しません。
- 取得・ページ移動・コピー・保存・待機などの動作には専用ブロックが必要です。

この試作は、既存の独立ブロックと互換性を保つため、パレットからの削除はまだ行いません。式の入れ子、オブジェクトの安全な編集、値を返す純粋なリスト操作は次の検証対象です。

テストでは既存の保存形式、出力名、元の入力値と式の保持、保存／復元／公開コード生成を確認します。新しい保存形式への移行は行いません。
