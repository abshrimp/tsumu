# スクリプトをブロックの組み合わせで表現する

## 通常パレット：6きっかけ＋16動作

「必要な操作が見つけられる」「ブロックをつなぐほど表現力が増える」ことを優先する。通常パレットでは副作用・制御・値の代入・値の加工を分ける。

| 種類 | パレットの役割 |
| --- | --- |
| きっかけ（6） | クリック、ホバー開始・終了、入力変更、ページ表示、画面内表示 |
| 外部とのやり取り（6） | データ取得、画面の表示変更、ページ/URL遷移、スクロール、入力欄の値変更、有効/無効 |
| データと保存（4） | 変数に値を入れる、値を加工する、ブラウザへ保存、保存した値の読込 |
| ブラウザ操作（1） | クリップボードへコピー |
| リストの表示（1） | 絞り込み・並べ替え・解除（表示状態を操作） |
| 制御（4） | 待機、条件分岐、回数繰り返し、リストの各項目を繰り返し |

合計16動作。**旧ブロックを削除したわけではない**。通常一覧から整理した10種類は「以前のブロックを表示」または検索で見つけられる。

## 加工はモーダルではなく、通常のブロックとして並べる

1. 「変数に値を入れる」で最初の値を用意する。
2. 次に「値を加工する」ブロックを配置し、入力元の変数と加工の種類を選ぶ。
3. 初期設定では出力変数を入力元と同じ名前にする。このとき同じ変数の値が新しい値に更新される。
4. 「値を加工する」を縦に追加し、別の加工を選ぶ。上から順に結果を使える。
5. 必要なら出力変数を別名にして、元の値をそのまま残す。

例えば、商品データから名前を表示する場合、以下の**5つの通常ブロック**を縦に組む。

- 取得した商品リストを変数 products とする
- productsを「価格が100より大きい」で絞り込んでproductsへ
- productsを「価格の降順」で並べ替えてproductsへ
- productsの各要素から「name」を取り出してproductsへ
- productsを「、」でつないで変数 displayNames へ

「変数を入れる」「値を加工する」「もし」「繰り返し」など、少数のブロックを組み合わせて処理を記述する。値加工の中に「外部通信」「表示変更」などの副作用は入れない。

## 値の加工ブロック

1ブロック1操作の実装。加工選択はブロック自身の設定であり、**加工を積み重ねる専用モーダルではない**。

- 値の取得：項目の取得、リストの位置指定、条件に合う1件、リスト全項目の指定項目
- 条件：項目の存在、件数、比較、真偽値反転
- 数値・文字列：加減乗除・余り、文字列化、JSON解析/文字列化、分割・結合・置換
- リスト：絞り込み、並べ替え、各項目への値の設定
- 補完：missing時、missing/null時の既定値

現在の加工は「元の値 → 1操作 → 出力変数」を厳密に評価する。複数ブロックを並べれば複数操作になる。型が合わない場合や危険なキー名ではエラーにし、出力変数を書き換えない。

「map-set」は固定した単純値を各項目へ入れる。任意の要素ごとの式や副作用は、将来のスコープ拡張／for-eachとの組み合わせで検討する。取得サンプルが先頭20件に切り詰められている場合、従来countとリストのlengthが一致するとは限らない。

## リスト表示の操作は値の加工と違う

「リスト表示を操作する」は、Webページ上でどの項目をどの順番で表示するかを変える。絞り込み・並べ替え・解除を選択して使う。操作を切り替えると、そのモード固有の条件は初期化されるので、直前の設定に戻す場合はUndoを使う。保存済みのfilter-array、sort-array、unfilter-arrayは引き続き読み込める。

「値を加工する」ブロックの絞り込み・並べ替えは**新しいデータとしてのリスト**を出力し、元のリストや画面のフィルター状態を直接変更しない。

## 後方互換と次に行うこと

- 旧set-var.value、保存済みrecipe、旧split/join/count/calc/replaceなどは読み込み・実行を維持する。
- 新しい値の加工ブロックは既存のscript.stepとして保存されるため、Undo/Redo、複製、公開書き出しで同じ順序を使う。
- サーバー配信前に値が確定している場合は配信前に計算し、画面上で値が決まる場合はブラウザで実行する。
- 古いブロックから新しい構成へ自動移行する処理はまだない。等価性が保証できるまでは強制移行しない。
- 今後は、ブロック間の入出力をさらに簡潔にする（前ブロックの出力を視覚的に示す／変数名を共有する）ことと、旧ブロックごとの互換性検査を進める。
