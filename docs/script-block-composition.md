# スクリプトエディタのブロック構成と型

## データ型

利用者向けの型は **「値」と「リスト」** の2種類とする。配列・辞書・オブジェクトは「リスト」にまとめ、「項目付きデータ」という独立した型は設けない。

- **値**：文字列、数値、真偽値、`null`。例えば `"123"`、`123`、`false`。
- **リスト**：配列、辞書、入れ子のJSONデータ。例えば `["a","b"]`、`{"name":"田中"}`。

内部のJavaScript/JSON型は維持し、表示名を統一するために配列を辞書に変換したり、数値を文字列に変換したりしない。数値演算では数値として解釈できる文字列を利用できるが、IDやキーに含まれる先頭ゼロは、元のデータを変更しない限り保持する。

値を直接入力した場合は、`12`、`true`、`null`、`[1,2]`、`{"a":1}` のように明確なJSONリテラルをその型として解釈する。数値に見えても文字列として扱いたい値は、`"0012"` のように二重引用符で囲む。`{変数}` を単独で入力した場合は元の内部型を保ち、通常の文字と変数を混ぜた入力は文字列になる。

## ブロックと条件

スクリプトは「きっかけ → 動作」の順に構成する。きっかけはクリック、ホバー開始、ホバー終了、値の変更、ページ読み込み、画面に入ったときの6種類。動作は表示・移動・入力・データ・変数・リスト・ストレージ・制御のカテゴリから選択する。

「値を加工する」の候補は次の **11操作** のみとする。

| 分類 | 加工 |
|---|---|
| 値の取得・補完 | リストから項目を取り出す、値がないとき別の値を使う |
| 数値・文字列の加工 | 数値を計算する、文字列を分割する、文字列を置き換える、リストを文字列につなぐ |
| リストの操作 | リストの項目数を数える、リストを並べ替える、リストに要素を追加する |
| JSONの変換 | JSON文字列に変換する、JSON文字列を読み取る |

文字列の分割・置換では、数値・真偽値を内部で文字列に変換する。元の変数の型は変えない。リスト、null、値がない場合は、文字列の加工の対象にしない。画面表示やURLなど、文字列が必要な箇所では、使う側で変換する。

「文字列を置き換える」で正規表現を使う場合、エディタと書き出したサイトは、式の分岐・繰り返しと入力の長さから、照合にかかる処理量を見積もる。見積もりが上限を超える場合は照合を実行しない。そのため、短い入力で使えた式でも長い入力では拒否されることがある。決まった文字列を探すだけなら、正規表現をオフにすれば長い入力でも置換できる。

条件の判定には「もし」を使い、リストからの選び出しや集計は「ループ」と「リストへの代入」を組み合わせて行う。

条件には「と同じ」「含む」「で始まる」「で終わる」「より大きい」「以上」「より小さい」「以下」「いずれかと同じ」「空」「項目が存在する」を使える。比較は数値・真偽値とその文字列表現を同等に扱う（`true` と `"true"`、`1` と `"1"` は一致）。`1` と `"01"`、`false` と `0`、`null` と `""` は一致しない。数値の大小は数値として比較できる文字列も受け付ける。

**「リストに含む」** は直下の各項目の **値** を探索する。**「項目が存在する」** は自分自身が持つ **項目（JSONのキー）** を調べる。例えば `{"apple":100}` は `100` を含み、キー `"apple"` が存在するが、値 `"apple"` を含まない。リスト同士が等しいかどうかは、キーと値を再帰的に比較して判定する。「リストに含む」と「項目が存在する」は、どちらも入れ子の中までは探さない。

条件は「である／でない」で反転でき、「かつ／または」で連結できる。「かつ」を先に評価してから「または」を評価する。未設定の条件は真と判定しない。

## リストの基本操作とループ

辞書を並べ替えた結果は、元のキーを失わないよう、`{ "キー": 元のキー, "値": 元の値 }` の項目を並べた配列として返す。配列を並べ替えた場合は、要素の形をそのまま保つ。どちらの場合も元のリストは変更しない。

「空のリストを変数にする」「リストの項目に値を入れる」「リストに要素を追加する」を組み合わせて、新しいリストを作る。配列では、キーを空欄にすると末尾に追加する。辞書では、キーを指定して追加・更新する。変数の値は元の値を書き換えずに更新し、危険なプロパティへの書き込み、極端に大きなインデックス、多すぎる処理件数は制限する。

「リストから項目を削除する」は、値で指定した場合は等しい値を持つ項目をすべて削除する（入れ子リストも「と同じ」の比較規則で判定する）。位置・キーを指定した場合は、配列なら0から始まる位置の1件を削除して後ろを詰め、辞書なら指定キーの1件だけを削除する。存在しない位置・キー、範囲外の位置、リスト以外の値では何もしない。削除後は元のリストを直接書き換えず、新しいリストを同じ変数に保存する。値・位置・キーは直接入力または {変数} で指定できる。

「リストの項目ごとにくり返す」は配列・辞書の両方で動作し、`null`、値、入れ子リストも処理する。ループの内側では次の値を使える。

| 参照 | 内容 |
|---|---|
| `{ループ.値}` | 現在の項目の値 |
| `{ループ.キー}` | 現在の項目（JSONのキーまたは配列の添字）を表す文字列。変数名は既存データを維持するため変更しない |
| `{ループ.順番}` | 0から始まる処理順 |
| `{ループ.外側.値}` | 入れ子のときの外側の項目 |

「ループを終了する」は最も内側のループだけを抜け、ループの後の処理は続ける。有限回の繰り返しと「ずっとくり返す」の両方で使用でき、ループの外では実行できないようにする。プレビュー・サーバーでの配信前処理・生成コードで同じ結果になることを検証する。

例えば、辞書のキーと値の組を一覧にしたい場合は、空のリストを作り、辞書の項目ごとにくり返して、`{ループ.キー}` と `{ループ.値}` を持つ行を追加する。条件に合う最初の1件を探す場合は、条件成立時に結果を保存し、その場でループを終了する。

## リスト表示とデータ保存

画面上のリストを「絞り込む」「並べ替える」「絞り込みを解除する」のは、変数の中身を変更することとは別の操作である。表示の絞り込みでは「かつ／または」「である／でない」を使える。

リストの項目数を数える場合、配列は要素数を、辞書は直下の項目数を返す。JSONを読み取った場合は、配列と辞書の区別を保つ。ストレージに保存したTsumuの値も、読み込むときに元の内部型を再現できるようにする。

データ取得のURL・メソッド・ヘッダー・本文と取得結果は、元のJSONデータの意味を保つ。値とリストの共通仕様は変数候補、スクリプト、ページ表示、エクスポート結果に適用する。

## 実行と検証

ページを開いたときのスクリプトでは、データ取得の後に続く純粋な演算・条件分岐・有限ループを、サーバー側で実行できる。画面操作・待機・ブラウザストレージなどに依存する処理はブラウザで実行する。サーバー・エディタ・生成コードで、計算結果が一致するようにする。

値がないときは、後に続く「値がないとき別の値を使う」で補えるようにする。一方、計算できない値・不正な型・無限大・ゼロ除算・実行上限の超過などはエラーとして扱い、誤った暗黙の型変換はしない。配列・辞書の項目参照や変数名の難読化によって、意図しないプロトタイプ参照やコード実行が起きないようにする。
