# ブラウザ側リストのテキストとページ変数の名前衝突

## 不具合

ページ変数 `name` が `First` で、ブラウザで展開するリストの項目が `First` と `Second` の場合、Canvasは項目ごとの名前を表示しますが、生成サイトでは両方が `First` になります。お手本を配信するときにページ変数で `{name}` が先行展開され、項目の値を入れる前にトークンが失われていました。

## 修正

ブラウザ側のお手本で、テキストが参照するトークン名と、配信時に解決済みの代替文字列だけを `data-text-parts` に保持します。項目がキーまたは根を持っていれば項目の値を優先し、未指定なら参照済みの代替文字列、その後に従来のブラウザ変数解決を使います。

要素自身の最初のテキストノードだけを書き換え、子要素は保ちます。空の代替テキストには必要なテキストノードを追加します。データから入った波括弧を再展開しません。元のお手本テキスト、rawコンテンツ、内側の非表示テンプレートはそのままです。項目全体やサーバーの変数全体はシリアライズしません。

## 検証

- 新規3 unitは修正前にすべて失敗し、修正後はすべて成功しました。
- 部品なし/あり、実SettingsPanelとScriptEditorによる設定、Canvas SSRと生成ランタイムの比較、繰り返し読込、行内スクリプト、ページ切替、保存文書の再読込を検証しています。
- null、空、未指定の子、ドット付きキー、slug、エスケープ、データと代替値に含む文字としてのトークン、子要素の保持、未使用private sentinelの不在を確認しました。
- 単独の修正で全1,076 unit、typecheck、i18n、エディタと生成Next.jsプロジェクトのWebpack本番ビルドが成功しました。独立レビューでも全1,076 unitと、空のテキストから子要素を保って値を入れるケースが成功しています。
- mainおよびサーバー側の親リスト修正と統合したtreeで全1,108 unit、typecheck、i18nが成功しました。統合treeの本番ビルドは公式CIで確認します。
- 通常のサーバーのみの生成プロジェクトは修正前と全ファイルが一致します。
- 実SettingsPanel、ScriptEditor、Canvas、保存ストア、生成ランタイムを使うネイティブ回帰を2件追加しています。ローカルでは未実行で、公式CI成功が必要です。生成Next.js全体のハイドレーション検査ではありません。

## 別の修正が必要な範囲

この変更はテキストだけです。リンクURL、画像src、フォームの初期値や案内文、シリアライズされたスクリプトの値は別の出力経路です。URLやJSONのエンコードと安全性、参照したサーバー値の代替を保ちながら個別に検証する必要があり、この変更で修正済みとはしていません。
