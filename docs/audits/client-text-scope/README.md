# ブラウザ側リストのテキストとページ変数の名前の衝突

## 不具合

ページ変数 `name` の値が `First` で、ブラウザで展開するリストの項目が `First` と `Second` だったとします。

- **Canvas** では、項目ごとの名前（`First` と `Second`）が表示されます。
- **生成したサイト** では、両方とも `First` になっていました。

**原因**: リストのお手本（テンプレート）を配信するときに、`{name}` がページ変数で先に展開されてしまい、項目の値を入れる前にトークンが失われていました。

## 修正

ブラウザ側のお手本には、次の2つだけを `data-text-parts` に残すようにしました。

- テキストが参照しているトークンの名前
- 配信時に解決済みの代替文字列

値は次の順で決まります。

1. 項目がそのキーまたは根を持っていれば、項目の値
2. 持っていなければ、参照済みの代替文字列
3. それもなければ、従来どおりブラウザの変数から解決

### 書き換える範囲

- 書き換えるのは、要素自身の最初のテキストノードだけです。子要素はそのまま残します。
- 代替テキストが空の場合は、必要なテキストノードを追加します。
- データに含まれる波括弧は、もう一度展開しません。
- 元のお手本のテキスト、rawコンテンツ、内側の非表示テンプレートは変更しません。
- 項目全体やサーバーの変数全体をシリアライズすることはありません。

## 検証

- **修正前後の比較**: 新しく追加した3つのunitテストは、修正前はすべて失敗し、修正後はすべて成功しました。
- **検証した操作**:
  - 部品（コンポーネント）なし・ありの両方
  - 実際の SettingsPanel と ScriptEditor による設定
  - Canvas の SSR と生成したランタイムの比較
  - 繰り返しの読み込み、行内のスクリプト、ページの切り替え、保存した文書の再読み込み
- **検証した値**: null、空の値、未指定の子、ドット付きのキー、slug、エスケープ、データや代替値に文字として含まれるトークン、子要素が保たれること、使われていない private sentinel が出力に含まれないこと。
- **単独での確認**: この修正だけを当てた状態で、全1,076件のunit、typecheck、i18n、エディタと生成した Next.js プロジェクトの Webpack 本番ビルドが成功しました。独立したレビューでも、全1,076件のunitと、空のテキストに子要素を保ったまま値を入れるケースが成功しています。
- **統合後の確認**: main と、サーバー側の親リストの修正を統合したツリーで、全1,108件のunit、typecheck、i18n が成功しました。統合したツリーの本番ビルドは、公式のCIで確認します。
- **影響がないこと**: サーバーだけを使う通常の生成プロジェクトは、修正前とすべてのファイルが一致します。
- **ネイティブの回帰テスト**: 実際の SettingsPanel、ScriptEditor、Canvas、保存ストア、生成ランタイムを使うテストを2件追加しました。ローカルでは**まだ実行していない**ため、公式CIでの成功が必要です。なお、生成した Next.js 全体のハイドレーションを検査するテストではありません。

## 別の修正が必要な範囲

この変更が直すのはテキストだけです。次のものは出力の経路が別なので、この変更では修正済みとしていません。

- リンクのURL
- 画像の `src`
- フォームの初期値や案内文
- シリアライズされたスクリプトの値

これらは、URL や JSON のエンコードと安全性、参照したサーバー値の代替を保ちながら、それぞれ個別に検証する必要があります。
