# サーバーで展開した親項目と、ブラウザ側の配列の名前が重なる場合

## 再現と原因

次のようなページを考えます。

- ページを開くときに取得した `items` を外側のリストにする
- 各項目の `tags` を内側のリストで並べる
- 同じ名前の `tags` を、クリック時のスクリプトでも変更する

このとき、**Canvas** は項目ごとの配列を使いますが、**生成したサイト** ではすべての項目にページの配列が使われていました。

**原因**: テンプレートを生成するときに、「内側の配列がブラウザで変わるかどうか」をページ単位でしか判定していませんでした。サーバーで展開済みの親項目は、ブラウザで作る行のスコープに含まれていませんでした。

## 修正の範囲

- JSX を生成するときだけ、ページ変数を含まない項目のスコープを保持します。
- 親項目が配列のキーまたは根を持っていれば、その項目の配列をサーバーで展開します。空配列・null・配列以外の値・ドット付きパスの未指定の子の場合も、ページの配列で埋め合わせることはしません。
- 親項目が根を持っていなければ、従来どおりブラウザ側のリストを使います。
- 生の取得配列・項目全体・使われていない項目を、新たにブラウザへ渡すことはありません。`data-item` に残すのは、既存の絞り込みの項目だけです。
- ブラウザ側の行のテキストが、同じ名前のページ変数で先に展開されてしまう問題は、この変更には含めていません。

## 検証

### unitテストとビルド

- 新しく追加した11件のunitテストのうち7件は、修正前に失敗しました。修正後は11件すべて成功しています。
- main のネイティブ入力の修正と統合したツリーで、全1,105件のunit、typecheck、i18n、エディタの Webpack 本番ビルドが成功しました。

### 検証した操作と値

- 部品（コンポーネント）なし・ありの両方
- 繰り返しの読み込み、行内のスクリプト、並べ替え・絞り込み・解除、ページの移動、保存した文書の読み直し
- 空・null・配列以外・未指定の根、ドット付きのキー、プリミティブの配列、表示件数
- 3段の入れ子と、ブラウザ側の子リスト

サーバーだけを使う通常の生成プロジェクトは、修正前とすべてのファイルが一致します。

ドット付きのキーについては、実際にブラウザ側と判定される根の変数を使う回帰テストを別に追加しています。サーバー側の通常の静的フィルターの回帰テストとは分けてあります。ブラウザ側と判定される配列で静的フィルターが使えることを、新たに保証する変更ではありません。

### 生成した Next.js プロジェクト

- 生成したプロジェクトは、手を加えないままでコンパイルと型検査に成功しました。
- テストでは架空の取得先を使っているため、そのままプリレンダーすると DNS の解決で失敗します。
- そこで取得モジュールだけを固定のテストデータに差し替えて本番ビルドしたところ、成功しました。RSC を含む出力に正しい4行があり、使われていない private sentinel が含まれないことも確認しました。生成した描画とランタイムには手を加えていません。

### ブラウザでの回帰テスト

Chromium の回帰テストでは、実際の SettingsPanel、ScriptEditor、Canvas、保存ストア、生成ランタイムを使い、次を検証します。

- 配列の選択、文字列を分割する入力
- undo/redo、保存した文書の再読み込み、プレビューへの入り直し
- 生成したサイトでの操作とページの移動

取得した配列を代入する処理そのものは、unit の SSR/DOM モデルの回帰テストでも検証しています。

ネイティブのテストはローカルでは**まだ実行していない**ため、公式CIでの成功が必要です。また、生成した Next.js 全体のハイドレーションを検証するテストではありません。

## マージの条件

ローカルの Node.js は 24 系で、宣言している 26.12.1 以上ではありません。対応するバージョンで動く公式CIの check・e2e と Cloudflare のビルドが成功したことを確認してから、マージします。
