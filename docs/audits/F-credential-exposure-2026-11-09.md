# 工程F：生成コードにおける認証情報の露出経路と設計判断

監査基準：`abshrimp/tsumu`、PR #30（`audit/F-export`）、2026-11-09
位置付け：既存機能の破壊を伴う秘密情報の保存形式変更は未実装。統括M・独立J・利用者による設計判断待ち。

## 1. 確認したコード経路

- `lib/generator/render-helpers.ts#fetchInitExpr` は取得ブロックのURL、ヘッダー名・値、JSON本文を、`codeLiteral` と `interpolate` / `interpolateJson` を使って生成コードに展開する。
- `lib/generator/page.ts#generatePageFile` はNext.jsのサーバーページに `fetchJson(...JSON.stringify(init) ...)` と `fetchPublic` 呼び出しを生成する。静的なヘッダー値・本文・URLは生成された `app/**/page.tsx` 等のソース中に残り得る。SSRで実行するという事実だけでは、公開GitHubリポジトリのソースを秘匿できない。
- `lib/generator/html-export.ts#pageFragment` はブラウザ用 `data-page-plan` をHTML内にJSONとして埋め込む。`lib/generator/react-export.ts` はブラウザ用のページプランと `data-loader.js` を生成する。
- `lib/generator/native-components.ts` / `native-scaffold.ts` はVue/Nuxt/SvelteKitの `site-routes.js` にページプランを展開する。Nuxt/SvelteKitでSSR実行する場合もソースそのものは出力物の一部であり、SSRレスポンスの `vars` に含まれる取得結果は訪問者に渡り得る。
- `lib/exportZip.ts` はフレームワークを問わず編集用 `_tsumu/doc.json` をZIPに同梱する。サーバー側実行用の秘密値だけを別コードに移しても、編集用SiteDocをそのまま保存すれば秘密値・取得見本がZIPに残る。
- `components/PublishModal.tsx` はGitHub Pushの直前に `hasPublishCredentials(target)` を実行し、判明した認証情報を含むSiteDocの公開を止める。公開前のこの**クライアント側**チェックは既に存在するが、任意のカスタムHTML/JS・未知のヘッダー名の秘密情報を完全には識別できない。ZIPダウンロードや公開済みの生成ファイルに同じ拒否を保証するものでもない。
- `lib/publish-security.ts` のスキャナーはURLクエリ、標準認証ヘッダー、JSON/フォーム本文、入れ子のスクリプトを探索する。PR #30のAUD-F-012で、ブラウザ向け出力は同じスキャナーを使い、百分率エンコード済みのキーやネストJSONの検出漏れを削減した。Metadata-Flavor等の既存拒否規則も保持している。

## 2. 入力種類別の露出評価

| 入力 | Next.jsの生成ソース | ブラウザ向け形式 | ZIP編集データ | GitHub Push |
|---|---|---|---|---|
| `Authorization: Bearer <literal>` 等、既知の認証用ヘッダー | `page.tsx` 等へ値を展開し得る | AUD-F-012で拒否 | 現行SiteDocのままなら含まれる | `hasPublishCredentials` が検出すれば拒否 |
| `Authorization: Bearer {token}` | プレースホルダー文字列・参照元の値が生成コードへ残り得る | ヘッダー名で拒否 | 参照元の設定と変数が残る | ヘッダー名で拒否 |
| URL内 `?api_key=...`（%エンコード名を含む） | URL文字列が生成コードへ残り得る | AUD-F-012で既知パターンを拒否 | URLを保持 | 既知パターンは拒否 |
| JSON本文の `password` / `client_secret` | 本文文字列が生成コードへ残り得る | AUD-F-012で既知パターンを拒否 | 本文を保持 | 既知パターンは拒否 |
| カスタムHTML/JS、独自名の秘密ヘッダー | 内容次第で生成物に残る | 任意コード文字列の完全な検出は未保証 | 内容を保持 | 網羅的には検出されない |
| `fetch.sample` 等の取得見本 | 通常のページデータ出力からは除く処理あり | ページデータプランでは除外 | 編集用データには残る | 生成時のSiteDocに含まれる |

注：表はコード経路からの評価であり、ランタイムの全組み合わせ・すべての入力を実行検証したという意味ではない。秘密値は現実のトークンを用いず、テスト専用文字列で確認する。

## 3. 未修正のセキュリティリスク

1. **ソース公開経路**：Next.jsサーバー側だけの処理でも、生成元コードを公開リポジトリに登録した場合、ハードコードされた値は公開される。Pushの既存UIガードには一定の効果があるが、完全保証ではない。
2. **アーカイブ経路**：編集用 `_tsumu/doc.json` は元の取得設定・取得見本を含み得る。ZIPを公開共有する場合はプレビュー用データの漏洩にも注意が必要。
3. **レスポンス経路**：キーをサーバー環境変数化しても、認証先のレスポンスを生成ページにレンダリングすれば、その内容はサイト訪問者に公開され得る。キャッシュ・ISR・プレビュー公開設定も独立して確認が必要。
4. **未知の秘密形式**：ヘッダー名やURLキーのブラックリストだけでは、独自形式やカスタムコード内の秘密を網羅できない。

## 4. 推奨設計（承認後に実装）

- 取得ブロックの資格情報は、単なる文字列ではなく「公開値」または「サーバー秘密参照」という区別を持つ入力モデルへ変更する。秘密値をSiteDoc、編集用ZIP、生成ソース、ブラウザ向けプランに保持しない。古い値へのサイレントなフォールバック・互換レイヤーは追加しない。既存データの移行はリポジトリ外の明示的な作業とする。
- Next.jsの認証付き取得では、公開値の直書きを拒否し、`process.env` 等の**サーバー専用環境変数**から実行時に解決する。 `NEXT_PUBLIC_` を使用しない。Cloudflare Workers等は対応するSecretsバインディングを個別に設計する。値を含まない `.env.example` とデプロイ設定手順のみ生成する。
- 環境変数が設定されていない場合は明確なエラーで停止する。ローカルデータや固定文字列へのフォールバックはしない。
- React、Vue、Nuxt、SvelteKit、HTML ZIP、単一HTMLなどブラウザから到達可能なデータ計画に、秘密参照・秘密値が混入する構成は拒否する。Nuxt/SvelteKitでSSRのみ実行してもページプランの含まれる生成ソースの公開には注意する。
- サーバー認証付き取得のレスポンスについては、一般公開可能なデータかを確認する。デフォルトで私的な結果を共有キャッシュ・ISRに保存しない。
- GitHub Push・ZIPダウンロード・生成APIを通じて同一の公開前安全性判定を行う。判定不能なカスタムコードは「機密情報を含まないことを確認する」警告を追加する設計を検討する。

## 6. マージ準備の安全性修正（AUD-F-018）

**2026-11-09：生成ファイルに認証情報を直書きする経路を既定で拒否する修正を実装。**

- `lib/export-formats.ts#exportLimitations` の資格情報検査を、ブラウザ向け形式だけではなく **Next.jsを含む全7形式**に適用。SSRのプログラムソースやZIP内の編集用`doc.json`も公開・共有され得るため、SSRであることを例外条件にしない。
- 既存の `hasPublishCredentials` を再利用し、URLの資格情報、既知の秘密クエリ、認証ヘッダー、本文の秘密値を含むときは、生成器を呼び出す**前**に明示的なエラーで停止する。GitHub PushとZIPの非同期入口も共通の生成処理を通る。
- 内部メタデータ用ヘッダーも、Next.jsを含めて拒否。正常な公開APIからのデータ取得は継続利用可能で、スクリプトエディタのデータ取得ブロックやプロジェクトの保存形式は変更しない。
- `tests/export-audit-f.test.mts` は全形式の拒否、Next.jsの直接生成／非同期生成、通常の公開データ取得、部分エクスポートの範囲境界、内部ヘッダーの拒否を検証する。

**互換機能の維持に関する明示事項：** 以前はNext.js生成ソースへの認証情報の直書きを許容していたが、その出力方法は公開リポジトリやZIP共有で資格情報を漏洩させるため、エクスポート時にエラーとなる。エディタ上の取得ブロック自体は削除しない。秘密値を用いる利用者は、秘密情報を含まない公開API／サーバー中継への変更、または生成後に秘密参照を手作業で安全に実装する必要がある。環境変数へ自動変換する機能は未実装であり、無断のサイレント変換は行わない。

**残存リスク：** カスタムHTML/JavaScriptなど任意の入力に混入した未知の秘密値は検出を保証できない。またデータ取得結果自体の公開可否はデプロイ側の責任で確認が必要。実運用の秘密参照機能への仕様拡張は別途設計審査対象とし、旧形式互換レイヤーは追加しない。

**統合チェック：** この変更を取り込んだ最新HEADの通常CI・追加スタイルビルド・E2E・CodeQL・独立レビューの結果を、マージ前に必ず再取得する。過去の27/27成功は根拠に使用しない。
