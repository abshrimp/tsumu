# 値を組み立てる — ブロックへ反映する版

「値の作り方」で既存ブロックを切り替える方式（#135）は採用しない。
「値を変数とする」の値を、元の変数に対する加工の列として保存する。

## UI

- 「元の値」を既存の階層付き変数メニューで選択する
- 「加工を追加」で目的別の4群から操作を追加する
- 加工は1行ずつ並び、必要な引数・上下移動・削除だけを表示する
- 「見本の結果」は最終結果のみを表示する。各行の説明と途中結果を常時出すUIは廃止
- 「ブロックに反映」で保存。キャンセルでは編集を破棄
- 保存後は元の変数と加工件数を表示し、「加工を編集」で再編集可能
- 「通常の値に戻す」は加工を外し、元の変数参照に戻す

項目名は直前の処理結果から候補を表示する。候補がない場合は「候補がありません」と明示し、自由入力は常に可能。候補メニューはモーダルのスクロールから独立して表示し、クリック時のフォーカス喪失で選択が消えないようにする。

## 加工の種類

| 分類 | 操作 | 内容 |
| --- | --- | --- |
| 取り出す | 項目を取り出す | オブジェクトのキーで取得 |
| 取り出す | リストから1件取り出す | インデックスで取得（0起点。-1は末尾） |
| 調べる | 項目があるか調べる | キーの有無を真偽値で返す |
| 調べる | リストの件数を数える | リストの要素数 |
| 変換する | 文字列に変換する | 文字列・数値・真偽値を文字列化 |
| 変換する | JSON文字列に変換する | JSONの表記でシリアライズ |
| 変換する | JSON文字列を読み取る | JSONテキストを値にパース |
| 補う | 値がないとき文字列を使う | missingのときのみ補完 |
| 補う | 値がないかnullなら文字列を使う | missingまたはnullで補完 |

「meta.name」は1つの項目名。入れ子の「meta → name」は加工2回。missingとnullは異なる。
HTTP通信、保存領域変更、ページ移動といった副作用は値の加工に含めない。演算やリストのフィルター、並べ替えは評価規則と両実行系を確認した後で追加する。

## 保存・実行

従来のset-varはvalue文字列のみ。新しいレシピを使った場合は既存stepに任意のrecipeを加える。

- recipe.source: 参照する元の変数名（階層を含められる）
- recipe.steps: 順番の付いた加工の列

レシピがなければ従来のvalue文字列で実行する。レシピがあればそちらを優先する。
保存時には値入力の元文字列として「{元の変数}」も残す。レシピを外すと、この従来の値参照へ戻る。
ブロックIDと出力先変数名は変更しない。Undo/Redoと保存・再読込は従来のstep更新を利用する。

加工は共通の純粋な評価関数で処理する。エディタの見本、サーバーでページを組み立てる処理、ブラウザのスクリプト実行で同じ規則を使う。サーバーのみで確定できる値は配信前に計算し、実行時に変わる値はブラウザのスクリプトに残す。元の入力データは書き換えない。

旧データへの一括移行や既存ブロックの削除は行わない。
