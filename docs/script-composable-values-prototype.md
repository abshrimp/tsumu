# 値を組み立てる — 保存と共通実行

「値の作り方」で既存ブロックを切り替える方式（#135）は採用しない。「値を変数とする」の中で元の変数を選び、加工を上から順番に積み重ね、**「ブロックに反映」**で保存する。キャンセルは編集を破棄する。

- モーダルは「元の値・加工一覧・見本の結果・反映」だけを常時表示する。操作の詳しい説明は選択肢のツールチップに置く。
- 既存のset-varブロックはvalue文字列を保持。加工時だけ追加のrecipeを保存し、旧データの意味は変えない。
- 保存・再読込・Undo/Redo・エディタの見本・生成Next.jsのSSR・公開ブラウザで同じ純粋な加工処理を使う。
- 変数名とブロックIDを維持し、「加工を編集」で再編集、「通常の値に戻す」で旧来の入力に戻せる。
- 項目候補は直前の加工結果から生成する。候補ゼロ／検索不一致を明示し、手入力もできる。

## 加工一覧（5群・20種類）

| 群 | 加工 | 用途 |
| --- | --- | --- |
| 取り出す | 項目を取り出す | データのキーを指定して取り出す。キー中のドットは1個の項目名 |
| 取り出す | リストから1件取り出す | インデックスで取り出す（0起点、-1は末尾） |
| 取り出す | 条件に合う1件を探す | 指定した項目を比較し、最初の1件を取得。なければmissing |
| 取り出す | 各項目から値を取り出す | リストのすべての要素から指定の項目を読み、新しいリストを返す |
| 調べる | 項目があるか調べる | 値がnullでもキーがあればtrue |
| 調べる | リストの件数を数える | リストの件数（現在の入力リストの長さ） |
| 調べる | 値を比較する | 型を保った比較。等しい／異なる／大小／含む／前方・後方一致 |
| 調べる | 真偽値を反転する | trueとfalseを逆転 |
| 計算・変換 | 数値を計算する | 加減乗除・剰余。数値以外と0除算はエラー |
| 計算・変換 | 文字列に変換する | 文字列・数値・真偽値を文字列へ |
| 計算・変換 | JSON文字列に変換する | データをJSON文字列へ |
| 計算・変換 | JSON文字列を読み取る | JSON形式の文字列を値へ戻す |
| 計算・変換 | 文字列を分割する | 区切り文字で分け、各項目の両端の空白と空要素を取り除く |
| 計算・変換 | リストを文字列につなぐ | null・空文字を除いた単純値リストを区切り文字で結合 |
| 計算・変換 | 文字列を置き換える | 文字列一致（全部）または正規表現による置換 |
| リスト加工 | 条件に合うリストを作る | 条件一致した要素だけの新しいリストを生成 |
| リスト加工 | 各項目に値を入れる | 各要素のオブジェクトへ指定した一定の値を設定した新リスト |
| リスト加工 | リストを並べ替える | 数値または文字列の項目で安定ソート。元のリストは不変 |
| 補う | 値がないとき文字列を使う | missingにだけ代替文字列を使う |
| 補う | 値がないかnullなら文字列を使う | missingとnullを補う |

「比較する値」「各項目に入れる値」は種類を選択する（文字列／数値／真偽値／null）。暗黙の数値変換はしない。リスト内で比較する項目は空欄なら要素自身、ドット区切りなら入れ子を参照（ただし同名の直下キーがあれば直下キーを優先）。マップで取得する項目が欠けているとエラーにし、結果を黙って削らない。

例：data.products →「項目を取り出す products」→「条件に合うリストを作る price > 100」→「リストを並べ替える price 降順」→「各項目から値を取り出す name」→「リストを文字列につなぐ 、」。副作用を伴う表示の絞り込みや取得リクエストとは別の、純粋な値計算になる。

## 仕様・制約

- **旧ブロックは削除・非表示にしない。** 分割・結合・件数・検索等との意味の違い（表示絞り込み後の件数、サーバーで取得した全件、文字列の暗黙変換、slug参照など）は引き続き同等性テストで確認する。
- 「リストを並べ替える」「条件に合うリストを作る」は**データとしての新リスト**を返す。「リスト表示の絞り込み・並べ替え」は別の画面状態操作。
- 「各項目に値を入れる」は現時点で**指定した一定の単純値を設定する操作**。要素の現在値や添字に基づく式、条件付き変換、項目削除は次段階の課題。
- 現時点で文字列結合は単純な値のリストが対象。オブジェクトなら「各項目から値を取り出す」などと組み合わせる。
- レシピは最大32工程、リストは最大10,000件などの上限がある。型が合わない／変数が欠落／JSONや正規表現が不正といった場合は明示的なエラー。数値以外を数値に暗黙変換しない。
- 比較におけるmissingとnullは異なる。値がない場合は後段の代替値操作で補える。
- 元データは直接変更しない。レシピは新しい値を生成して出力変数へ代入する。
- 旧来のset-var.valueは維持し、recipeがあるときだけrecipeを優先。旧来の保存形式は読み込める。

## パレット整理の次の条件

独立したsplit、join、count、array-find、array-field、calc、replaceなどは、このレシピの「似た」加工を持つだけでは取り除かない。実行場所（サーバー／ブラウザ）、データの型、URL slug、配列件数と表示フィルタ、エラー・スコープなどが一致することを回帰テストで確認し、初めて追加パレットから段階的に隠す。既存スクリプトの読み込み・編集・実行・公開は維持する。全体設計は docs/script-block-data-audit.md。
