# 値を組み合わせるUI試作

「値の作り方」を選択して既存ブロックを別の種類に変える案（#135）は取りやめました。
代わりに、**入力値に複数の加工を順番に重ねる**UIを検証します。

## 操作例

`data = { items: ["A", "B", "C"] }` を元の値として選択した場合:

1. 「項目を取り出す」: `items` → `["A","B","C"]`
2. 「リストの件数を数える」 → `3`
3. 「文字列に変換する」 → `"3"`

利用者は1つの値の加工として並べ、順序変更・削除ができます。元の値に対する変換であり、既存ブロック同士の切り替えはありません。

## UIの確認方法

スクリプト画面で「値を変数とする」ブロックの **「値を組み立てる」** を開きます。
「元の値」は変数を階層ごとに選べるドロップダウンから指定します。項目を取り出す操作では、直前までの加工で得た項目付きデータをもとに項目名候補を表示し、候補にない項目名も直接入力できます。「加工を追加」で処理を順に追加してください。見本があれば結果をその場で確認できます。

加工の順番は上矢印・下矢印で変更できます。アイコンボタンには操作名のラベルも付けています。

取り出す項目名 `meta.name` は1つの項目名として扱います。
入れ子の `meta` → `name` を取り出す場合は、「項目を取り出す」を2回続けます。
リストの要素は「リストの位置を取り出す」で数値の添字を指定します。

存在しない値（missing）はnullと区別します。
「値がないとき文字列を使う」はmissingのみを補い、値がnullならそのまま残します。
型が合わない操作は無言で変換せず、エラーとして見本に表示します。

## 保存・公開実行について

**これは画面内で見本を評価するだけの試作です。** 「加工を試す」画面を閉じても元の値・スクリプト・保存データ・公開コードは変更しません。
試作UIから既存の `SiteDoc` に式を保存する処理はまだありません。

評価には #119 の純粋な型付き式基盤をそのまま用いており、次の制約を持ちます。
- JSON値とmissingを厳格に区別する
- 参照、項目取得、リスト添字、件数、明示的な文字列化、JSON変換、missing時の既定値が対象
- 四則演算、リストの純粋な加工、実行時の通信・ストレージ更新などはまだ実装していない
- サンプル用データがない場合には結果を推測しない

## 製品機能化の前提

将来的にスクリプトへ式を保存するには、既存文書と両立する式の保存形式、サーバー・プレビュー・公開クライアントで共通の評価規則、既存 `set-var` の読み込みとUndo/Redo、スコープ・変数の変更、変換できない式のエラー表示をそれぞれ検証する必要があります。

それらの確認前に既存ブロックを削除したり、既存データを新形式へ一括変換したりしません。
