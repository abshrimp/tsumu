# 値を組み立てる（見本専用UI）

「値の作り方」で既存ブロックの種類を切り替える案（#135）は採用しない。
値に対して複数の操作を**上から順に重ねる**方式を試作している。
この画面で作った加工手順は、現時点でスクリプトの保存・プレビュー実行・公開サイトには接続しない。

## 操作の流れとUI

1. **元の値**：階層付きの変数メニューから値を選び、その見本を確認する。
2. **加工する順番**：目的別の4群から加工を追加する。各手順に説明と途中結果を表示し、上下のSVG矢印で並べ替え、ゴミ箱で削除できる。
3. **見本の結果**：幅のある画面では右側に表示してスクロール中も確認でき、狭い画面では手順の後ろに並ぶ。

「項目を取り出す」「項目があるか調べる」では、**直前の加工結果**が項目付きデータの場合、その項目名を候補として出す。候補が0件なら「候補がありません」、入力文字列に一致するものが0件なら「一致する候補がありません」と表示し、どちらの場合も任意の項目名を直接入力できる。

候補一覧はモーダルのスクロール領域から独立したポップアップとして配置する。候補内のクリックやキーボード確定をフォーカス解除で取りこぼさず、スクロール時には入力欄の位置を追従する。候補の外側クリック、フォーカス移動、Escでは閉じる。

## 加工の種類（4群・9種類）

| 群 | 種類 | 役割と注意 |
| --- | --- | --- |
| 取り出す | 項目を取り出す | 項目付きデータからキーで取得。ない場合はmissing。 |
| 取り出す | リストから1件取り出す | 先頭を0とする添字で取得。範囲外はmissing。 |
| 調べる | 項目があるか調べる | キーの存在有無をtrue/falseで返す。値がnullでも存在すればtrue。 |
| 調べる | リストの件数を数える | リスト全体の長さを取得。文字列の長さとは別。 |
| 変換する | 文字列に変換する | 文字列・数値・真偽値を通常の文字列に変換。リスト・項目付きデータはエラー。 |
| 変換する | JSON文字列に変換する | JSONとして値を文字列化。リスト・項目付きデータにも利用可能。 |
| 変換する | JSON文字列を読み取る | 文字列のJSONを解析して値へ戻す。不正なJSONはエラー。 |
| 補う | 値がないとき文字列を使う | missingのときだけ文字列で補う。nullはそのまま。 |
| 補う | 値がないかnullなら文字列を使う | missingとnullの両方を文字列で補う。 |

### 意味の違い

- 「meta.name」は**1個の項目名**として扱う。入れ子の「meta → name」を参照するには「項目を取り出す」を2回追加する。
- 「0」はリストの最初の要素。リスト件数の見本が保存時に先頭20件で切られている場合、元データの実件数と一致するとは限らない。
- 項目の存在を調べる操作は、その項目の値がnullでもtrue。値が存在しないmissingはnullと同じではない。
- 「文字列に変換する」と「JSON文字列に変換する」は別。後者では文字列をJSON化すると引用符が付き、リストもJSON配列の形で保持される。
- エラーは自動で空文字や0にせず、該当する手順と結果の両方で確認できる。

例：元の値が data = { items: ["A", "B", "C"] } のとき、
「項目を取り出す（items）」→ ["A","B","C"]、
「リストの件数を数える」→ 3、
「文字列に変換する」→ "3" となる。

## なぜこの9種類か

現在の型付き式エンジンで、**入出力の型と意味を明示して見本評価できる**加工だけをUIに出す。
旧来の「件数」「計算」「文字列分割」などの独立ブロックを別の種類へ切り替える仕組みにはしない。
特に四則演算、文字列の置換・分割・結合、リストの検索・加工・絞り込み・並べ替えは利用価値が高いが、型・エラー・スコープ・実行環境の同一性を定めてから、**次段階の値加工として検討**する。

値の純粋なリスト加工と、リスト表示の絞り込み・並べ替えは違う。通信・ブラウザ保存・ページ遷移などの副作用も値の加工には含めない。

## 検証と製品機能化

- レシピ、見本データ、入力中の候補、並べ替え・削除はモーダル内だけの状態。
- この画面を閉じてもSiteDoc、公開コード、実行時の値は変化しない。
- 型付き式の純粋な評価基盤（#119）を使用しており、サーバー・プレビュー・公開サイトの統合は未実装。
- 保存形式を追加する際は既存のset-var、Undo/Redo、変数名変更・スコープ、読み込み互換性、生成コードとサーバー実行の同等性、エラー表示を検証する。
- 既存ブロックは同等機能が実際に動作するまで削除・非表示にしない。
