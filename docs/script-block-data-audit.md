# スクリプトのブロック整理とデータ操作（レビュー案）

この文書は、スクリプト画面にある **きっかけ6種類・動作25種類** の棚卸しです。
このPRでは検索UIだけを試作し、ブロックの削除・保存形式・実行コードは変更しません。

## 操作を分類する基準

- **動作**：通信、ページ遷移、画面操作、クリップボード、ブラウザ保存など、実行すると外側の状態が変わるもの。
- **値の操作**：取得・参照した値から新しい値を作る、計算・文字列加工・リスト加工など。将来は「変数に値を入れる」の値欄に統合する。
- **表示への操作**：リスト表示の絞り込み・並び替え・解除。データとしてのリストを加工する純粋な操作とは別に扱う。
- **制御**：分岐と繰り返し。実行順・スコープ・待機の意味を持つ。

JSONの `[]` は「リスト」、`{}` は「項目付きデータ」、繰り返し画面に出す要素は「リスト表示」。
「一覧」はページ一覧など、単なる表示一覧に使う。

## 現行25動作の棚卸し

| 現行キー | 役割 | 方針 | 残すべき意味 |
| --- | --- | --- | --- |
| `fetch` | HTTP経由のデータ取得 | 独立動作として維持 | 非同期、送信先、取得の実行タイミング |
| `show` | 表示／非表示／切替 | 維持 | 3動作は既にパレットの1項目 |
| `open-page` | ページ／URLへ移動 | 維持 | 2動作は既にパレットの1項目 |
| `scroll-to` | 要素へスクロール | 維持 | 画面の副作用 |
| `set-value` | フォーム入力欄に値を設定 | 維持 | 変数への代入とは異なる |
| `set-enabled` | 入力欄の有効／無効 | 維持 | 入力要素の操作可能状態 |
| `split` | 文字列をリストにする | 値の操作に統合候補 | 空項目の処理・区切り文字 |
| `join` | リストをつなぎ文字列にする | 値の操作に統合候補 | サーバーの取得配列を含む |
| `count` | リストの件数を返す | 値の操作に統合候補 | 保存見本の20件制限と実件数は別 |
| `array-find` | 条件に合う1件を探す | 値の操作に統合候補 | 見つからない場合とnullを区別 |
| `array-field` | リスト内の各項目に格納 | 仕様確認後に統合 | 実行の位置・項目スコープ・書換え可否 |
| `for-each` | リストの各項目で動作を実行 | 制御として維持 | 項目・番号スコープと副作用 |
| `filter-array` | リスト表示を絞り込む | 表示操作として維持 | 元のリスト自体は加工しない |
| `unfilter-array` | 表示絞り込みを解除 | 表示操作に統合候補 | 番号別解除と全解除の区別 |
| `sort-array` | リスト表示の順序を変える | 表示操作として維持 | 純粋なリストのソートとは別 |
| `store-save` | ブラウザの保存領域へ書く | 独立動作として維持 | 永続化の副作用 |
| `store-load` | 保存領域から読み込む | 当面維持 | 読込時期・欠落・既定値 |
| `set-var` | 変数へ値を代入 | 値入力の中心として維持 | 名前のスコープと代入時点 |
| `calc` | 計算して代入 | 値の操作に統合候補 | 数値の型と型変換の明示 |
| `replace` | 文字列を置換して代入 | 値の操作に統合候補 | 正規表現・キャプチャ・不正な式 |
| `list-edit` | 区切り文字付き文字列の追加・削除・切替 | 仕様確認後に統合 | **JSONリストではなく文字列操作** |
| `copy` | クリップボードへコピー | 独立動作として維持 | ブラウザ権限とユーザー操作 |
| `wait` | 時間待機 | 制御として維持 | 非同期・順序 |
| `if` | 条件で分岐 | 制御として維持 | 条件と入れ子構造 |
| `repeat` | 指定回数または無限に繰り返す | 制御として維持 | 停止と待機 |

きっかけ6種類（クリック、ホバー開始、ホバー終了、入力変更、ページ表示、画面内表示）は別の開始条件なので、動作の統合対象にしない。

## 追加が必要な値の操作

| 要望 | 値欄の操作候補 | 注意点 |
| --- | --- | --- |
| 項目を取得・確認 | 「項目を取り出す」「項目があるか」 | `["meta.name"]` と `["meta","name"]` を混同しない |
| 項目を更新・削除 | 「項目を設定」「項目を削除」 | 元データは直接変更しない |
| 各項目を加工 | 「各項目を変換」「条件で絞る」 | リスト表示の状態とは区別 |
| リストを並べ替え | 「並べ替えたリスト」 | 画面の並べ替えと異なる |
| 欠落の対処 | 「値がなければ」「nullなら」 | missingとnullは別 |
| 型変換 | 「JSONとして読む」「文字列に変換」 | 暗黙の型変換を避ける |
| 条件 | AND・OR・NOT | 短絡評価とエラー伝播 |
| 型判定 | 文字列／数値／真偽値／null／リスト／項目付きデータ | 値ごとの候補表示 |

#119の型付き式は、これらを値として合成する方向の独立した内部基盤ですが、
現在のUI・保存・runtime・generatorには未接続です。#119をそのまま採用する前提にはしません。

## 段階的なUI変更

1. **操作を探す（このPR）**：用途・動詞・旧称で既存パレットを絞り込む。既存の全操作を維持。
2. **値欄の試作**：`set-var`の値欄から、件数・結合・計算などを選んで組み合わせる。種類別の独立ブロックを増やさない。
3. **データと表示の分離**：リストの加工とリスト表示の絞り込みを別の言葉・UIで明示する。
4. **新規追加の整理**：同等機能が確認できてから、旧独立ブロックを追加候補から段階的に隠す。保存済みブロックはそのまま読み込む。

## 後続の検証と移行条件

- **プレビュー・保存／再読込・Undo／Redo・公開HTML・生成コード**で同じ意味になること。
- 実行場所（ページ読込前のサーバー／ブラウザ）と通信・ストレージの副作用を維持すること。
- 変数・リストの項目・添字のスコープと名前変更を検証すること。
- 既存保存データの全件バックアップ、復元手順と実データ復元検査を行うこと。
- 新形式へ移す場合は互換性を持つ移行前リリースを先に配信し、既存データの移行を確認すること。
- データ移行と両実行系の検証が完了するまで旧形式の読み込みコードを削除しないこと。

**このPRでは永続化スキーマ・実行処理・書き出し内容を変更しません。**
