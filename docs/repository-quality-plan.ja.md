# Tsumu 全体の品質改善計画（2026-11-11）

## 対象と進め方

開始時の main は `1bbae469`。作業対象の母集団は、このコミットの `git ls-files` に含まれる923ファイルとする。下表は機能別の担当範囲で、複数領域を結ぶファイルは呼び出し元と先を一緒に確認する。画像やライセンスを含む追跡ファイルの棚卸しと、実装の行単位の監査は区別して記録する。

1. 基準を固定する。追跡ファイルの内訳、テスト・ビルド・ベンチマークの入口を記録し、既存の修正と重複する作業を除く。
2. 下表の各領域について通常操作を入口にコードと既存試験を照合する。データの消失、認可・機密性、意図しない外部通信を最優先にし、操作の誤り、繰り返し実行される重い処理、重複実装を続けて扱う。
3. 修正ごとに影響する呼び出し元を確認する。既存試験で拾えない不具合には回帰試験を追加し、修正前・修正後で結果を比較する。性能変更は同じ入力・条件で所要時間または処理回数を測り、結果の同値性も確認する。
4. 領域をまたぐ変更を統合し、型・翻訳・単体・ブラウザ操作・ビルドを確認する。CIの失敗は該当ジョブと変更の関係を調べ、修正後のコミットで再検証する。
5. 実施範囲、結果、実行環境の制約と残課題を記録する。各領域は「修正・検証済」「重点経路を点検」「未検証」の範囲を明記し、確認した経路から領域全体へ結論を一般化しない。

CI指定の Node 26.12.1 と npm 12.2.1 を基準とし、ロックファイルを使用する。局所試験の後、`npm run typecheck`、`npm test`、`npm run i18n:check` を実行する。PRのCIでWorkersビルド、Docker起動、依存監査、Playwrightの4分割、生成形式5種類のTypeScript／JavaScriptビルドを確認する。性能の記録には入力件数・反復数・環境を併記する。実データ・本番環境の変更は計画に含めない。
